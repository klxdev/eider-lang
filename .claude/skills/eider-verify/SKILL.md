---
name: eider-verify
description: Run the full Eider verification matrix (compile-fail suite, run tests on gcc/clang/ASan/TSan, the compiler against its recorded oracle, the seed, C/C++ export, WebAssembly, and the editor tooling eider-analyzer and tree-sitter-eider). Use after any compiler change.
---
Run `scripts/verify.sh` from the repo root. It must end with `ALL GREEN`. It needs only a C compiler for the compiler itself (`scripts/ei` builds `target/eiderc-stage0` from `seed/eiderc.wasm`, and with clang 17+ `target/eiderc` from compiler/); clang, sanitizer runtimes, wasm-ld and node are needed for the legs that use them (a missing one is reported as `skip`).
After a change to `compiler/`, also run `sh scripts/selfhost.sh --seed` (must print `SELF-HOSTED`) and commit `seed/eiderc.wasm` and `seed/eiderc.wasm.clang`.
If a change is meant to alter observable behaviour (diagnostics, run output, headers), run `BLESS=1 sh scripts/test-compiler.sh`, review `git diff tests/oracle` (and the goldens), and commit the expected files with the change.
New error codes need an entry in `diag.all_codes()` (`compiler/diag.ei`) and a `tests/checks/fail/*.ei` file (`// expect: CODE LINE:COL`; the header is line 1).
A syntax or IDE-visible change updates the grammar and analyzer in the same wave (LAYERS.md, "Tooling"): new syntax goes into `../tree-sitter-eider` (grammar.js, `npx tree-sitter generate`, the queries, a `test/corpus` case, `npx tree-sitter test`) and into `../eider-analyzer` (the lexical stand-in, completion and hover lists, a session test; `sh tests/run.sh`), each committed in its own repository. The "tools (eider-analyzer, tree-sitter-eider)" leg of verify.sh (`scripts/check-tools.sh`) builds and tests the analyzer against this checkout and parses every `.ei` file with the grammar; it is skipped only when a repository or tool is missing, and a FAIL there blocks ALL GREEN like any other leg.
