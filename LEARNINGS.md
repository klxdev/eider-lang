# Eider compiler learnings

- If checking and C emission are one pass, every expression whose operand emits hoisted statements must re-order its earlier operands, and a missed case shows up as wrong evaluation order, not a crash (`tests/run/order.ei` catches it). eiderc avoids the class with a typed IR between `check` and `lower`.
- Compile-fail headers (`// expect: CODE LINE:COL`) count the header as line 1. Verify positions against the source by hand before blessing.
- Constant folding runs before codegen, so deliberately-bad runtime-trap tests must use variables, not literals (`(300 as i64) as u8` is a compile error).
- Statements on one line need `;`. Newline is the separator; `{` must follow the signature (same or next line).
- Generated C uses `INTn_C`/casts for literals and `_Noreturn`; keep it C11 with no builtins so any `$CC` works.
- The list of every error code lives in `compiler/diag.ei`; add new codes there (with a compile-fail test) or the coverage line goes stale.

# Language design learnings (from design phase)

- Name: Eider. Extension `.ei`. CLI `eider`. Code-fence tag `eider`.
- `.ei` is only partly verified (truncated FileInfo page). GitHub Linguist is unchecked.
- Don't rename with broad `sed` on `tern`/`Tern`: it retags unrelated code fences (`extern` contains `tern`), and case-insensitive passes mangle comments ("AUTO-generated"). Use `\b` and check `extern` is untouched.
- WebFetch only accepts URLs that already appeared in a search result. Search first, then fetch.
- N-API exposes Eider to Node. Calling JS from Eider means embedding QuickJS.
- `interop_examples.md` is stale: it still shows TOML annotation files and `project.toml`. The decided design is in-language `extern c "..." as name { ... }` blocks plus a declarative `project.x` manifest, with an opt-in `build.x`.
- Competing agent-oriented languages: Edda, Vera, Keel.
- Top-level `uses` is not valid; capabilities are per-fn. `for i in 0..4` with literal bounds gives i32 (cast to index).
- Type decl variants need a leading `|`. Prelude (Option/Result) is Eider source in `core/prelude.ei`, parsed before user items.
- Stripping redundant parentheses from generated C must be string-literal aware; clang warns on `if ((a == b))`.
- References (C8.6): `let` of a place no longer copies, so code that read a place into a `let` and then wrote the place silently changes meaning. An audit build of the checker that reports every write overlapping a live reference (not only invalidating ones) found all such sites in the repository; `.copy()` at the binding keeps the old meaning under both the seed and the new compiler. Run it again before a change of binding semantics.
- Ownership model (S2): value semantics. Reading owned data out of a place clones; fresh rvalues (temporaries) move. Params are borrowed. Frames = per-block drop lists; return/break/continue/`?` drop outer frames. Pattern bindings clone (no aliasing).
- A mutating method receiver (push/insert/...) must stay a place; never hoist it into a by-value temp while ordering operands (that leaked a List in the first draft).
- Closures capture a snapshot (clone) in a heap env; can't mutate captured vars. Value-form closure bodies (`if`/`match`/block) need a return type from context or `-> T`.
- Modules (S4, namespaced in S7): `import "x.ei" [as y]`; items are private unless `pub` (E0801). Module prefix = file stem; its top-level names are renamed `stem__Name` and the parser turns `alias.Name` into the same identifier, so the checker still sees one flat table. Two files with the same stem conflict (E0808). `extern` fns stay global (C symbols). A local named like an import alias breaks `alias.x`. Compile-fail runner must pass the real path so imports resolve; helper modules live in tests/checks/{fail,pass}/lib/ (runner doesn't recurse).
- extern "c" fns are declared as `extern T f_name(..) __asm__("name")` to dodge clashes with libc headers (ELF-only: Mach-O would need the `_` prefix). Need `uses ffi` + `unsafe`.
- `export fn` => non-static `eider_<name>` wrapper + header (`eider build --lib`); traps in a library exit(101).
- Threads (S5): Task/Mutex/Chan are refcounted heap handles; closures hold snapshots so threads share only via Mutex/Chan. `spawn` needs `uses threads`; `Chan.new()` needs a type annotation (E0409). Build with `-pthread`. Verified under TSan. eiderc (C7): handles are `{ struct X_c *p; }` over eider_rt's ei_rc/ei_thread/ei_mutex/ei_chan with per-type glue only; the last Task handle joins its thread before freeing, so `main` never ends with a thread running (docs/compiler.md, "C7: threads").
- WASM (S6): `build --wasm` compiles generated C with clang --target=wasm32 against a tiny freestanding libc (bump/free-list malloc, printf, host imports `env.eider_write/eider_now_ms`). Exports are ints/bool only (E0806); threads rejected. `exit`/traps become wasm `unreachable`. Needs clang+wasm-ld (`WASM_CC` overrides).
- WASM in eiderc (C7): the runtime and libc are `core/wasm/` (README there), not pasted into every build. Gotchas: clang turns 64-bit overflow checks (`__builtin_mul_overflow`, and the `n > MAX / size` idiom) into `__multi3` calls, which `-nostdlib` leaves as an unresolved `env` import that fails at instantiation, so libc.c defines it. The generated JS loader breaks for an export parameter named `x` (it shadows `const x = inst.exports`) and returns unsigned values above the signed range as negative numbers/BigInts; it is kept byte-identical to the recorded expectations, so both bugs remain (C8 candidates in docs/compiler.md). printf output is no longer cut at 511 bytes (`compiler/tests/wasm/long.ei`).
- Comptime: `const X: T = comptime expr` compiles the program minus main/tests with a synthetic `main` printing the value, runs it, splices a literal back. Evaluator has no capabilities (E0201 with the fix stripped), ints/bool only (E0807). Evaluated sequentially, so later comptime consts can use earlier ones.
- Build cache: `run`/`build` key binaries on fnv64(cc, flags, libs, generated C) in `$EIDER_CACHE` (default ~/.cache/eider; `off` disables). Whole-program front end is not incremental; only the C compile is skipped.
- `scripts/verify.sh` (skill: .claude/skills/eider-verify) is the full matrix; run it after any compiler change.
- `run`/`test` compile C at -O0 (gcc ~4x faster than -O2 on a 3k-line program); `build` and `run --release` use -O2. Every non-unit function (and closure body) ends in `ei_unreachable()` or gcc -O0 warns `-Wreturn-type` and pollutes test output.
- eiderc's run tests check drops with a counting allocator (`EIDER_CFLAGS=-DEI_RT_COUNT_ALLOCS`: generated `main` reports `eider: outstanding allocations: <n>`), because ASan's runtime isn't installed everywhere. To test eiderc on its own source before FFI lands, stub core/sys.ei's `extern "c"` fns in a scratch copy (docs/compiler.md, "C5: lowering").
- Self-hosting (C6): `scripts/selfhost.sh` reached the fixed point on its first run because lowering was already deterministic (no index-based names, no map iteration, no paths in the C) and tested with a stubbed-FFI copy first. Scripts that run a compiler from another directory must take an absolute path (`EIDERC=` is one). After any `compiler/` change: `sh scripts/selfhost.sh --seed` and commit seed/eiderc.c.
- The recorded oracle (C7): expected results live in `tests/oracle/` (one file per (command, input), the checkout's root written `<root>`, because one E0808 message prints absolute module paths), and the tests read them instead of running a second compiler. When it was recorded, the oracle-reading test-compiler.sh was first run green while the reference implementation was still present, so the switch kept the tests' strength. From now on expected behaviour changes only through `BLESS=1 sh scripts/test-compiler.sh` and a reviewed `tests/oracle` diff. Don't overwrite `target/eiderc` with a compiler built from `compiler/`: `scripts/ei` treats it as the seed build (test-compiler.sh uses `target/eiderc-next`).
- Fuzzing without a second compiler: the first consistency run (checked programs must build) flagged mutants declaring `extern "c"` fns that nothing defines, so programs with externs are checked but not built. Unbounded recursion ends in SIGSEGV (no stack guard), so the fuzzer counts SIGSEGV apart from other signals.
- Compile-time benchmark (3,000-line synthetic, 150 record types, 2 cores, no cache): front end ~50 ms; gcc -O2 4.9 s, -O0 1.3 s; clang -O2 ~19 s, -O0 0.5 s. The C is ~3.7x the Eider line count because every type gets its own glue; shrinking that is the main lever.

# Behaviour eiderc fixed or kept deliberately

The recorded expectations (`tests/oracle/`; docs/compiler.md, "History") include some wrong behaviour. Where eiderc fixes it, the case has a regression test with hand-written expected output (`compiler/tests/run/bug_*` and others named below); where it keeps it for compatibility, the quirk is a C8 candidate in docs/compiler.md, to be fixed deliberately with a `BLESS=1` oracle update. `compiler/` still avoids the `else if` temporary and the match-arm shadowing patterns below (the seeds so far were built from such code; keep it that way, it costs nothing).

- Fixed: owned temporaries in an `else if` condition (e.g. `else if bytes.eq(x, sys.lit("a"))`) were declared inside the generated `else { }` block but dropped after it, so the C failed to compile (`tN undeclared`). In `compiler/`, still bind the value first or compare through a helper function.
- Fixed: a match arm binding with the same name as the `let` it initializes (`let p = match r { Ok(p) => p ... }`) was emitted as a second C variable inside the arm's block, so the outer `p` was never assigned and read garbage (an early `main.ei` crashed in `ast.at`). In `compiler/`, still give the binding another name.
- Fixed: `len(e)` on an array folded to the length and never evaluated `e`, so side effects in `e` were lost; eiderc's IR keeps them.
- Fixed: folding `u64 * u64` constants overflowed 128-bit arithmetic and crashed the checker. eiderc computes in 128 bits; there is no oracle test for it, since nothing was recorded.
- Kept: checker quirks eiderc reproduces for diagnostic parity (docs/compiler.md, "C3: checking"): `Enum.Variant` on an imported module's enum is E0114; some errors in imported modules name the importer's file; a module's test block doesn't let locals shadow the module's item names.
- Fixed: string literals were pasted into the C with only `"`, `\`, newline and tab escaped, so `??(` and the other trigraphs turned into `[` etc. under `-std=c11` (plus a `-Wtrigraphs` warning on stderr). eiderc escapes `?` (regression test `compiler/tests/run/bug_trigraph.ei`).
- Not reproduced: `?` in a closure whose body is an expression (`|x| f(x)?`) was checked against the *enclosing* function's return type (the body was checked before the closure's return type was set), and the C returned the wrong type. eiderc answers `unsupported` there; block-bodied closures (`|x| -> T { ... }`) are fine.
- Kept: checker quirks found while porting S1–S3: when a declared type is unified with an actual one, a name that isn't a type parameter matches any type, so a bound is met by any type once some `impl Trait for Name` exists, and `impl W[i32]` methods apply to every `W`; registering an impl replaces `Self` textually, also inside `MySelf` (C8 candidates; `compiler/tests/check/fail/e0115_quirk_bound_name_target.ei`).
- Fixed: at -O2 gcc reported `-Wmaybe-uninitialized` on temporaries declared before a branch that always assigns them. Harmless, but eiderc's C must be warning-free.
- Not reproduced: an `extern "c"` or `unsafe fn` used as a function value (`let f: fn(i32) -> i32 = abs`) passed the checker with neither `unsafe` nor `uses ffi` (only the declared capabilities were checked), and the value could then be called anywhere. eiderc answers `unsupported` there until the language decides (an unsafe fn type, or an error).
- Fixed: `emit-header` gave only parameter and return records a typedef, so a header whose record has a record field didn't compile. eiderc typedefs every record (compiler/tests/export/nested.ei).
- Kept: comptime quirks eiderc keeps for parity (docs/compiler.md, "C7: comptime"): each comptime constant's evaluator program lacks every comptime constant not yet evaluated, so a plain `const` naming a comptime constant always fails (E0110), and so does any function naming a later one; any error in the rest of the program is found by the first evaluator, and an E0201 there loses its fix wherever it is. Traps during evaluation name the file `program`.
- Fixed: `Mutex.update(f)` dropped `f` inside the generated update function and the caller dropped it again (the closure was passed while still registered for a drop), so a closure that captures anything owned was freed twice. `set`/`update` also dropped the old value while holding the lock, which deadlocks when the value holds the last handle of a Task whose thread needs that lock. eiderc borrows the closure and drops after unlocking (`compiler/tests/run/bug_update_capture.ei`).
- Fixed: a method of the value `Mutex.get` returns, inside a call argument (`String.from_int(m.get().len() as i64)`), was emitted as `void tN = ;` (C didn't compile); eiderc emits it correctly (`compiler/tests/run/bug_get_method_arg.ei`).
